# 福彩店推荐系统 — 设计方案

> 定位：给福彩店老板的「理论依据」工具，不是预测中大奖，而是提升顾客体验、建立专业形象。

---

## 1. 项目背景

### 1.1 核心事实
- 福利彩票（双色球、福彩3D、七乐彩等）**理论上是完全随机事件**。
- 每期开奖独立，历史数据不包含任何跨期预测信息。
- 任何 ML/DL/LLM 模型无法在单期预测上击败随机选号。

### 1.2 老板的真实需求
| 老板说的 | 实际含义 |
|----------|----------|
| "我需要一个推荐号码的系统" | 顾客需要"有依据"的选号建议 |
| "要有理论依据" | 老板自己也需要觉得"这不是瞎推荐" |
| "提高预测准确率" | 提高顾客满意度和回头率 |

**结论**：项目目标不是"中头奖"，而是**"让顾客觉得这家店专业、靠谱"**。

---

## 2. 福彩长期玩家的分析方法（用户画像）

### 2.1 "科学派" — 高级赌徒谬误
| 方法 | 原理 | 实际效果 |
|------|------|----------|
| 遗漏分析 | 某号 N 期没出，"该出了" | 独立事件，概率不变 |
| 热号追踪 | 近期热号会继续热 | 独立事件，无记忆 |
| 和值/跨度 | 和值趋于均值附近 | 长期成立，单期无用 |
| 奇偶/质合比 | 偏离均值会回归 | 同上 |
| AC值 | 算术复杂度趋于中间值 | 同上 |
| 旋转矩阵 | 覆盖法，N 个号中 M 个 | 提升中小奖概率，不改变期望 |
| 缩水过滤 | 设定条件砍掉不符合的组合 | 砍掉头奖的概率和被砍组合一样 |

### 2.2 "技术派" — 软件化的高级赌徒谬误
- 频率统计软件
- 神经网络/LSTM 预测
- 遗传算法
- 蒙特卡洛模拟

### 2.3 "玄学派" — 真正的用户心理需求
| 方法 | 内容 |
|------|------|
| 梦兆解号 | 梦见蛇=3，鱼=6，龙=5 |
| 生辰八字 | 出生年月日对应幸运数字 |
| 五行缺补 | 缺火=多选 2、7（火数） |
| 周易起卦 | 摇卦得数对应号码 |
| 车牌/手机号 | 用自己的幸运数字 |
| 忌日/纪念日 | 重要日期数字 |
| 直觉/灵感 | "感觉这期要出 8" |

## 3. 推荐系统的价值定位

### 3.1 核心价值
| 价值 | 实现方式 |
|------|----------|
| **降低顾客决策成本** | "我不知道选什么" → "老板推荐一个" |
| **增加互动和粘性** | 顾客觉得"有分析"，更愿意常来 |
| **提升专业形象** | "这店用大数据分析" vs "那店随机打" |
| **减少输钱后纠纷** | 明确标注"基于历史统计，不保证中奖" |

### 3.2 免责话术
> "本推荐基于历史数据统计，仅供娱乐参考，不保证中奖。请理性购彩，量力而行。"

## 4. 具体落地方案

### 4.1 机选 + 分析并存
- **随机选号**：保证公平性
- **"本期分析"小票**：热冷号/遗漏/和值区间（打印或微信推送）
- **历史对战**："上期推荐命中 X 个"（不管中不中，有反馈感）

### 4.2 多策略推荐
| 策略 | 描述 | 目标用户 |
|------|------|----------|
| **保守型** | 热号为主 + 和值均值区间 | 稳健玩家 |
| **激进型** | 冷号回补 + 偏态奇偶比 | 冒险玩家 |
| **平衡型** | 均匀分布 + AC值中间区间 | 无明显偏好 |
| **玄学型** | 融合用户生日/幸运数字 | 玄学派玩家 |

### 4.3 反赌徒谬误工具（科普/信任建设）
| 工具 | 形式 | 效果 |
|------|------|------|
| 热冷号 vs 随机选号对比图 | 店内海报/电子屏 | "这老板实在，不忽悠" |
| 和值分布直方图 | 小票背面 | 长期规律可视化 |
| "策略对战"排行榜 | 小程序/网页 | 娱乐化展示策略长期表现 |
| 遗漏提醒 | 微信推送 | "XX 号已遗漏 30 期，历史最大遗漏 45 期" |

## 5. 技术架构

### 5.1 数据层
| 组件 | 技术 | 说明 |
|------|------|------|
| 数据源 | 500.com / 中彩网 / GitHub 开源数据集 | 双色球 2298 期历史数据 |
| 数据格式 | CSV | 期数 + 红球 1-6 + 蓝球 1 |
| 更新机制 | 每周自动抓取 | 增量更新 |

### 5.2 分析层
| 组件 | 技术 | 说明 |
|------|------|------|
| 特征工程 | Python + Pandas | 热冷号/遗漏/和值/跨度/奇偶/质合/AC值 |
| 多策略引擎 | 自定义 | 保守/激进/平衡/玄学四种策略 |
| 随机选号 | Python random | 均匀分布，保证公平 |

### 5.3 输出层
| 组件 | 技术 | 说明 |
|------|------|------|
| 小票打印 | ESC/POS 指令集 | 打印推荐号码 + 分析摘要 |
| 微信推送 | 企业微信 API | 推荐号码 + 历史对战 + 遗漏提醒 |
| 可视化 | Matplotlib / ECharts | 对比图 / 直方图 / 排行榜 |

## 6. 实施计划

### Phase 1：MVP（最小可行产品）
- [ ] 数据管线：500.com 抓取 → CSV 存储
- [ ] 多策略推荐：保守/激进/平衡/玄学四种
- [ ] 小票输出：推荐号码 + 分析摘要
- [ ] 历史对战：上期推荐命中数

### Phase 2：增强
- [ ] 微信推送：遗漏提醒 + 推荐号码
- [ ] 反赌徒谬误可视化：对比图 / 直方图
- [ ] 策略长期表现排行榜
- [ ] 蓝球推荐（目前只做红球）

### Phase 3：扩展
- [ ] 福彩3D / 七乐彩 / 大乐透支持
- [ ] 用户历史：记录顾客常买号码，个性化推荐
- [ ] 小程序/网页：顾客自助查询

## 7. 已知风险与对策

| 风险 | 对策 |
|------|------|
| 顾客质疑"为什么不中" | 明确标注"基于历史统计，不保证中奖" |
| 模型被滥用为"预测工具" | 所有输出附带"仅供娱乐参考"免责声明 |
| 数据源失效 | 多数据源（500.com + 中彩网 + 本地缓存） |
| 玄学数字与统计冲突 | 两种模式分开输出，不强行融合 |
